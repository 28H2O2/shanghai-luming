# 上海鹿鸣 · 上海路名收藏册

双击 `dist/index.html` 即可打开路名地图。地图、搜索、筛选和故事都能离线使用。在线访问 [上海鹿鸣](https://shanghai-luming.vercel.app)。

默认显示市中心。地图优先标出公园、校园和地标。指向或轻点有名的街道会显示路名，点击收藏圆点、彩色道路或目录里的路名可打开故事。点开道路后，左上角的缩略图会用红点标出它在上海的位置。点缩略图或再点已选道路，即可回到总览；已选道路会继续高亮，筛选条件也会保留。用 Tab 聚焦圆点可读路名，按回车打开。“全部道路”把宝山和浦东大团也放进视野，这一档就是当前屏幕能缩到的最远范围。筛选后的同一按钮显示“筛选结果”。支持拖动、滚轮、双指缩放及键盘方向键、加减键。手机上地图在上，故事在下。

地图现收录 52 条道路。打开[江湾五角场地图](https://shanghai-luming.vercel.app/?area=江湾五角场)，可以一起看环岛的五条马路、复旦附近的大学路和国福路、新江湾城的恒耀路，以及此前收录的世界路。全图有 50 条道路画出了具名路段，零点大道标到宝杨路口，大团镇海潮路标到川南奉公路交叉口。定位精度与路名由来的可信度分别记录。

## 路名与沿革考证

收录一条路，先弄清现名的来历，再查它何时修筑，哪些路段曾经延伸、合并或改名。优先选得名有据、沿革也有具体史实可写的道路。

先用现名和所在区查《上海地名志》、区志的道路条目，以及命名、更名公告。现名找不到时，换旧名、异写、街镇名或沿线地物继续查。老地图能帮你认出不同时期的路名和走向，再用图上的旧名找档案、旧报刊和地方文史研究。例如，老地图可以指出肇嘉浜的位置。要写“肇嘉浜路沿用了河名”，还需找到明确记载这层关系的原文。同音、相邻或出现年代的先后，都只能作为检索线索。

打开原文核对，把出处记入 `sources`，在 `scope` 写明它支持哪项事实，尽量注明卷章、页码、图名或段落。多篇转载同一材料只算一个出处。若两份资料记的年份不同，先看各自说的是开工、命名还是挂牌。仍有分歧，就在 `notes` 中注明各自的说法和出处。

资料直接说明得名缘由时标为“已查证”。只有流传说法时标为“传说”，注明是谁记录的。沿旧名和地物继续查找后，若仍只能证实筑路或改名经过，就把命名缘由标为“待考”，`story` 留空，在 `notes` 保留已经查实的沿革并注明出处。交接或汇报时写清查过哪些资料、哪一点仍待证，方便下一位接着找。

## 增补一条路

1. 在本目录打开终端，运行下面的命令，保持窗口开启。
2. 打开 `data/roads.yaml`，复制一条相近的记录，加入最外层列表，记录间用英文逗号分开。改好路名和内容后保存。
3. 终端会自动校验每次保存，通过后重新生成页面。刷新已打开的 HTML 即可看到改动。出错时会列出记录序号、路名与字段，上一版页面仍可阅读。按 Ctrl+C 结束监听。

```sh
python3 scripts/validate.py --watch
```

数据使用 YAML 1.2 兼容的 JSON 写法，键名和文字用英文双引号，末项后不加逗号。Python 3 标准库即可读取。每条实际道路单独建档，同名路各填其行政区，并可在备注里相互指认。

| 字段 | 填写方式 |
| --- | --- |
| `name`、`district` | 现名与现属行政区。跨区可写“静安区、长宁区”。 |
| `old_names` | 旧名列表，年代能核实就附在相应名称后。没有资料时填 `[]`。 |
| `area_group` | 选一个区域分组。跨界道路按有据可查的代表路段归档，可在备注注明口径；城厢外的街道可归“其他”。 |
| `naming_type` | 类型列表，可多选；未查明时填 `[]`。已知由来超出枚举时选“其他”，例如沿用园林名。 |
| `credibility`、`story` | 资料直接记载了路名来历时填“已查证”，地图显示“由来有据”。只有流传说法时填“传说”，地图显示“民间传说”，并附记载该说法的出处。这两类故事均用自己的话写 100～200 字，含标点、忽略空白。现有资料能证实道路、却没有解释命名时填“待考”，地图显示“由来未详”；故事留空，也兼容旧记录里的“待考”占位文字。 |
| `sources` | **每条道路**至少一个出处。每项包含 `title`、`url`，可加 `scope` 写明它能支持的具体事实或原文所在页。待考也可引用能证实路名、位置的资料。 |
| `notes` | 个人备注，无内容时填空字符串。未经证实的猜想写明“推测，无出处”。 |
| `fun_fact`、`pinyin` | 可选。有资料支持的小细节，以及用于路牌排版和检索的拼音。 |
| `location` | 地图定位对象，含 WGS84 经纬度、精度、说明及定位出处，详见下文。暂缺坐标可省略，记录仍可检索。 |
| `legend` | 可选。如果另有传说，在这里填一个对象，含 `text` 和这则传说自己的 `sources`。页面另起“民间传说”一栏。 |

**区域** 可选老城厢、原公共租界、原法租界、虹口北外滩、江湾五角场、浦东、徐汇滨江、其他。

**命名类型** 可选租界省市名、河道桥梁遗存、行业作坊、起讫型、谐音讹传、人名、纪念性改名、行政区名、当代新命名、其他。

以零点大道为例，一条可收录的精简记录如下。数据里已有这条路，新增时可复制它并替换内容。

```json
{
  "name": "零点大道",
  "old_names": [],
  "district": "宝山区",
  "area_group": "其他",
  "naming_type": [],
  "story": "",
  "credibility": "待考",
  "sources": [
    {
      "title": "宝山区政府 · 吴淞口活动交通管制通告",
      "url": "https://www.shanghai.gov.cn/nw17239/20250928/4ef8bd1a58cf442a851e3b326fb98fa9.html",
      "scope": "核对零点大道与宝杨路交会的位置。"
    }
  ],
  "notes": ""
}
```

## 给道路定位

`location.point` 一律使用 **WGS84 [经度, 纬度]**。用 OpenStreetMap 上有名称的街道、路口或其他可复查的地物核对地图与资料，并在 `location.sources` 列出依据。只拿到高德或百度坐标时，需先核对其坐标系。道路位置可暂缺，避免把镇政府或行政区中心当作路的位置。

- `kind: "line"` 表示有道路几何。另填 `paths`，每条连续线段是一个经纬度点列表。分开的线分别保存，避免跨街连线。`point` 取在线上的代表点。当前 OSM 道路还保存了原始 `way_ids`。
- `kind: "point"` 表示已核实到某一处路口。用 `description` 说明具体路口和定位方法。
- `kind: "area"` 表示只确认到片区。说明参考地标和已经确认的地理范围。后两类均省略 `paths`。

取折线时，先核对道路两端，再在上海路网摘录中查齐同名路段，按行政区和路口排除异地同名路。分隔车道要分别核对两个方向，交叉口和桥面以共享节点确认接续。单个 OSM 路段可能只覆盖两盏红绿灯之间；只能确认局部时，在定位说明中写清范围。

例如，零点大道的路口参考点取宝杨路东端的 [OSM 节点 474867925](https://www.openstreetmap.org/node/474867925)，经纬度为 `[121.49906, 31.40509]`。完整记录与政府附图链接在 `data/roads.yaml` 中。更新地理数据后，监听命令也会重做页面。

## 底图与署名

`assets/shanghai-map.json.gz` 包含裁切、简化的路网、水系、地名和绿地，数据来自 [Geofabrik 上海 OSM 摘录（2026-11-16）](https://download.geofabrik.de/asia/china/shanghai.html)。长江口等水面以 [OpenFreeMap](https://openfreemap.org/) 的 [OpenMapTiles](https://openmaptiles.org/) 2026-11-15 图层补齐。公园、校园和场馆的重点标注见 `data/landmarks.json`，坐标取自同一摘录的对应地物面内，并保留 OSM 对象编号。显示时采用上海附近的等距圆柱投影，北向上。底图取经度 120.96°～121.97°、纬度 30.77°～31.59°，收藏道路周边保留更多支路。大比例尺下可以看走向，不能用于测量道路红线。

地理数据按 [Open Database License 1.0](https://www.openstreetmap.org/copyright) 提供，© OpenStreetMap 贡献者。可在页面“收录说明”中下载完整底图与道路定位数据。底图的压缩整数格式、原点和换算公式在下载文件的 `encoding` 字段中。署名使用从 Macintosh Skeletal Filled 提取的 “made by H2O2” 字形。在线版单独缓存字体，离线版把字体嵌在页面里。

缩略图采用 [Natural Earth 1:10m Admin 1](https://www.naturalearthdata.com/downloads/10m-cultural-vectors/10m-admin-1-states-provinces/) v5.1.1 的上海轮廓（CN-SH，WGS84），简化后存于 `data/shanghai-outline.json`。市域轮廓、底图中的黄浦江和选中道路共用同一投影。收藏道路使用记录中的代表点，普通街道使用点击位置在路段上的最近点。

界面用暖灰和米白作底，取意外滩石材；砖红用于页头和选中道路，取意上海历史街区的砖墙。可参阅[上海市政府发展研究中心的城市色彩调研](https://www.fzzx.sh.gov.cn/zdkt_2018/20200117/0053-10523.html)及[外滩、衡复风貌区建筑色彩研究](https://ch.whu.edu.cn/article/doi/10.13203/j.whugis20250342)。

## 单独校验与生成

```sh
python3 scripts/validate.py
python3 scripts/validate.py --build
```

第一条命令只校验。第二条通过校验后，用 `templates/` 中的页面、样式、地图交互脚本和 `assets/` 中的素材生成两个入口。双击 `dist/index.html` 可离线使用全部功能，也可以单独分享这个文件。在线版生成在 `out/`，首页包含路名故事、道路定位和主要水系，详细底图随平移或缩放按视野加载；插画在打开收录说明时加载。也可把另一份数据文件的路径作为校验脚本的位置参数，单独检查。结构检查覆盖字段、枚举、字数、链接格式和传说出处，资料能否证明某个命名说法仍需阅读原文判定。

本地更新后，将新版本发布至同一 Sites 项目，在线页才会随之更新。发布前运行 `--build`，站点入口为 `out/index.html`。Sites 配置见 `.openai/hosting.json`。收录说明中的电车街景为创作插画。

Vercel 从 GitHub 仓库 `28H2O2/shanghai-luming` 的 `main` 分支部署。推送后，Vercel 按 `vercel.json` 的配置运行上述校验和构建，将 `out/` 发布到 [上海鹿鸣](https://shanghai-luming.vercel.app/)。校验或构建失败时，线上继续使用上一次成功的版本。`out/assets/` 里的文件名都带内容哈希，`vercel.json` 让浏览器把它们缓存一年，回访时只需重新取首页。
